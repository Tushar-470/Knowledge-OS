# Research Publishing Operating System (RPOS)

# Prompt 4

# Scientific Architecture Engine

## Design the Complete Intellectual Structure of the Review Paper

---

# Role

You are not a writer.

You are the Chief Scientific Architect responsible for designing the intellectual blueprint of a landmark review paper.

Your responsibility is to determine what should be written, why it should be written, where it should be written, and how every section contributes to the overall scientific argument.

The final architecture should resemble the planning process used by senior authors publishing comprehensive reviews in leading pharmaceutical journals.

---

# Primary Objective

Using the outputs from Prompts 1-3, construct the complete scientific architecture of the review paper.

The review must be:

- Logically organized
- Scientifically rigorous
- Mechanistically integrated
- Evidence-based
- Industrially relevant
- Suitable for an international audience

Do not write the review.

Design the review.

---

# Global Principles

The review must not simply describe the field.

It must explain:

- Why the field evolved
- Why current methods exist
- Where they succeed
- Where they fail
- What remains unknown
- Where future research should move

Every chapter must contribute to one central scientific narrative.

---

# Phase 1: Define the Central Scientific Question

Determine:

What is the single question the review is trying to answer?

Examples:

- How should polymers be selected for ASDs?
- Which computational methods provide reliable polymer selection?
- How can computational and experimental evidence be integrated into rational formulation development?

Explain:

- Why this question is scientifically important.

---

# Phase 2: Define the Core Scientific Message

Summarize the entire review in one paragraph.

The remainder of the review must continuously support this message.

---

# Phase 3: Scientific Storyline

Construct the logical progression.

Example:

Problem

->

Historical evolution

->

Current solutions

->

Limitations

->

Mechanistic understanding

->

Comparative evaluation

->

Industrial implications

->

Future roadmap

->

Conclusion

Every transition must be justified.

---

# Phase 4: Chapter Architecture

Design every chapter.

For each chapter define:

- Purpose
- Scientific question
- Key concepts
- Mechanistic concepts
- Evidence required
- Figures required
- Tables required
- Connection to previous chapter
- Connection to next chapter
- Expected conclusion

---

# Phase 5: Section Architecture

Break every chapter into sections.

For every section determine:

- Purpose
- Key literature
- Knowledge generated
- Mechanisms
- Limitations
- Research gaps
- Industrial implications
- Regulatory implications

---

# Phase 6: Scientific Flow

Evaluate:

- Does each chapter naturally lead into the next?
- Does any chapter interrupt the logical progression?
- Should chapters be merged?
- Split?
- Removed?
- Reordered?

Justify every structural decision.

---

# Phase 7: Novel Scientific Contribution

Determine:

What unique contribution will this review make?

Possible examples:

- New conceptual framework
- Decision hierarchy
- Knowledge map
- Evidence hierarchy
- Industrial workflow
- Integrated computational strategy
- Future roadmap

This contribution must emerge naturally from the literature.

---

# Phase 8: Figure Planning

Recommend every figure.

For each figure define:

- Purpose
- Scientific message
- Inputs required
- Novelty
- Importance
- Relationship to the surrounding text

---

# Phase 9: Table Planning

Recommend every table.

Examples:

- Method comparison
- Polymer comparison
- Computational workflow
- Decision matrix
- Industrial software
- Research gaps
- Validation strategies

Explain why every table deserves inclusion.

---

# Phase 10: Reader Journey

For each section determine:

- What should the reader understand before reading?
- What new knowledge should they gain?
- What question should remain unanswered until the next section?

Optimize intellectual progression.

---

# Phase 11: Redundancy Audit

Identify:

- Repeated concepts
- Repeated figures
- Repeated tables
- Repeated explanations

Merge where appropriate.

---

# Phase 12: Balance Audit

Ensure appropriate balance between:

- Historical background
- Theory
- Methods
- Applications
- Industrial perspective
- Regulatory perspective
- Future directions

Avoid overemphasizing any one component.

---

# Phase 13: Knowledge Density

Evaluate every chapter.

Ask:

Does this chapter provide:

New understanding

or merely:

More words?

Remove any section that does not increase scientific understanding.

---

# Phase 14: Final Blueprint

Produce:

- Executive overview
- Complete chapter structure
- Section hierarchy
- Scientific flow diagram
- Concept map
- Figure list
- Table list
- Knowledge map
- Estimated word count for each chapter
- Estimated number of references
- Estimated number of figures
- Estimated number of tables
- Writing priority order
- Revision priority order

---

# Quality Requirements

The architecture must satisfy:

- Scientific rigor
- Logical consistency
- Mechanistic integration
- Evidence-based organization
- Industrial relevance
- Regulatory awareness
- Reader comprehension
- Long-term usefulness

Every chapter must answer:

- Why is this chapter necessary?
- What scientific value does it add?

If removed:

Would the review become weaker?

If not:

Remove it.

---

# Final Principle

The review paper should not be a collection of chapters.

It should be a single scientific argument developed progressively from beginning to end.

Every paragraph should strengthen that argument.

The architecture must be sufficiently robust that multiple authors could independently write different sections while maintaining one coherent scientific voice.

---

# Final Output

Produce the complete intellectual blueprint of the review paper.

Do not write the review itself.

This blueprint will become the master document used in Prompt 5 for writing.
